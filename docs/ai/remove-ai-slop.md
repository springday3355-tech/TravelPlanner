# Remove AI Slop

> "동작은 하지만 이 프로젝트 컨벤션과 안 맞는 코드"를 걸러내는 기준. 작업을 끝내기 전에 아래 항목을 스스로 점검한다.

## 과잉 구현

- 요청받지 않은 기능을 "혹시 필요할까 봐" 미리 만들지 않는다 (예: 1단계인데 캐싱 레이어, 재시도 로직, 커스텀 어노테이션을 미리 추가).
- PRD에 없는 설정 옵션, 프로퍼티, 토글 플래그를 임의로 늘리지 않는다.
- 이미 있는 공통 골격(ApiResponse, GlobalExceptionHandler 등)을 도메인별로 재구현하지 않는다.

## 가짜 안전장치

- 실제로 검증하지 않는 null 체크, 항상 true인 조건문, 의미 없는 try-catch(그리고 로그만 찍고 삼키는 예외 처리)를 넣지 않는다.
- 테스트가 실제로 아무것도 검증하지 않으면서(assert 없음, 항상 통과) "테스트 추가함"이라고 보고하지 않는다.
- 컴파일만 되고 실행/테스트로 확인하지 않은 코드를 "완료"로 보고하지 않는다.

## 불필요한 장식

- 사용하지도 않을 TODO 주석, 플레이스홀더 메서드, 빈 구현체를 남기지 않는다.
- 모든 줄에 주석을 달지 않는다 — 왜(why)가 필요한 곳에만 짧게 단다. 무엇(what)은 코드 자체로 드러나야 한다.
- 네이밍을 이 문서 세트(SA/DB설계/정책)에 나온 용어와 다르게 임의로 바꾸지 않는다(`itinerary` vs `trip`, `place` vs `spot` 등 혼용 금지).

## 일관성

- 기존 코드 스타일(패키지 구조, 예외 처리 패턴, 응답 포맷)과 다른 새로운 패턴을 같은 문제에 대해 또 만들지 않는다.
- 같은 종류의 CRUD를 도메인마다 다른 방식으로 짜지 않는다 — 먼저 구현된 도메인의 패턴을 따른다.

## 보고

- 실제로 한 일과 다르게 부풀려 보고하지 않는다. 빌드/테스트를 못 돌렸으면 못 돌렸다고 말한다.
- "결정 대기" 항목을 조용히 임의로 채워놓고 언급하지 않는 것도 이 문서가 금지하는 행위다.
