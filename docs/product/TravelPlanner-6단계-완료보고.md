## 2. 이번 단계 구현

### 운영 데이터베이스

- `local`, `test`, `prod` 설정을 분리했다.
- 운영은 MySQL 드라이버와 `prod` 프로파일을 사용한다.
- 운영에서 Hibernate는 `validate`만 수행하며 스키마 변경 권한은 Flyway에만 둔다.
- DB 계정, 비밀번호, JWT 비밀값은 환경변수로 주입한다.

### 버전 마이그레이션

- `V1__create_core_schema.sql`에 현재 7개 도메인 테이블을 정의했다.
- 외래키, 유니크 제약, 일정·장소 조회 인덱스를 포함했다.
- CI에서 빈 MySQL 8.4 DB에 마이그레이션을 적용하고 Flyway 검증과 테이블 생성을 확인한다.

### 컨테이너 실행

- Java 21 멀티 스테이지 `Dockerfile`을 추가했다.
- 애플리케이션을 비루트 사용자로 실행한다.
- Compose에서 MySQL 상태 확인 후 애플리케이션을 시작하며 앱의 `/api/health`도 컨테이너 상태 검사에 사용한다.
- `.env`는 Git에서 제외하고 `.env.example`에는 변수 이름과 비민감 기본값만 제공한다.

### 운영 절차와 로그

- 최초 실행, 배포, 마이그레이션, 백업, 복구, 종료 절차를 운영 런북에 기록했다.
- 운영 SQL과 바인딩 값 로그를 끄고 오류 응답에서 내부 메시지와 스택 추적을 제외했다.
- 로그와 백업에 대한 비밀값, 보존, 접근 원칙을 명시했다.

## 3. 검증 기준

- 로컬 Gradle 테스트 43개 중 일반 테스트 42개 통과, 실패·오류 0개. MySQL 전용 1개는 CI 환경변수가 없어서 조건부 제외됐다.
- `git diff --check` 통과.
- 필수 비밀값을 임시 주입한 `docker compose config --quiet` 통과.
- 로컬 Docker Desktop 엔진이 실행 중이지 않아 실제 컨테이너 기동은 PR의 `MySQL migration` 작업에서 검증한다.
- PR의 `Gradle test`, `MySQL migration` 검사가 모두 성공해야 병합한다.

## 4. 제한과 다음 단계
